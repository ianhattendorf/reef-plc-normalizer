# Repository Guidelines

## Repository Role and Structure

This repository packages the Reef PLC Normalizer as a Home Assistant App. Root
metadata is in `repository.yaml`; the app lives under `reef_plc_normalizer/`:

- `config.yaml`: Home Assistant App metadata and options.
- `Dockerfile` and `run.sh`: container build and startup.
- `app/src/`: Rust modules for config, contract validation, layout, MQTT,
  normalization, availability, and Home Assistant discovery.
- `app/packed_mqtt_layout.yaml`: PLC field map plus stable discovery metadata.
- `app/contracts/plc_mqtt.json`: sanitized snapshot generated by the private PLC repository.
- `README.md`, `DOCS.md`, and `CHANGELOG.md`: user and release documentation.
- `scripts/`: contract synchronization and release tooling.

This repository is the protocol adapter, not the control authority. The private
`../aquarium-controller-plc` repository owns PLC source, publisher timing, raw
topics, payload order, LWT, and command subscriptions. Live Home Assistant
configuration is managed through the Home Assistant MCP server;
`../home-playbook` records durable operating policy rather than live HA state.

## Build, Test, and Development Commands

Run commands from the repository root:

- `cargo fmt --manifest-path reef_plc_normalizer/app/Cargo.toml -- --check`
- `cargo clippy --manifest-path reef_plc_normalizer/app/Cargo.toml --locked -- -D warnings`
- `cargo test --manifest-path reef_plc_normalizer/app/Cargo.toml --locked`
- `scripts/sync-plc-contract.sh --check ../aquarium-controller-plc`
- `scripts/check-release.sh`
- `docker build reef_plc_normalizer`
- `scripts/release.sh patch` for a validated patch release; the script also
  accepts `minor`, `major`, or an explicit version.

## Contract and MQTT Invariants

Any raw PLC topic, field, width, type, timing, QoS, retention, LWT, or command
change must begin in the PLC repository. Regenerate its contract, refresh this
repository's snapshot, update the layout without changing established discovery
IDs unnecessarily, and audit all Home Assistant consumers before release.

- PLC status/LWT and normalizer status/LWT are retained.
- Raw telemetry, normalized state, clock, and command publications are non-retained.
- Home Assistant discovery is retained; removed discovery uses an explicit retained tombstone.
- Unconditional PLC publishers are the heartbeat; do not add a separate heartbeat topic.
- Ten-second telemetry expires after 60 seconds; the five-minute clock expires after 390 seconds.
- Every PLC-backed data entity requires both PLC and normalizer availability.

Keep MQTT topics, discovery unique IDs, default entity IDs, state JSON keys, and
alarm acknowledgement keys stable unless an intentional migration includes a
complete consumer search and tombstone/update path.

## Coding and Testing

Use standard Rust formatting and snake_case names. Keep layout entries explicit:
normalizer state key, optional authoritative `plc_source`, packed length, value
type, and discovery metadata. Prefer focused modules over adding behavior back
to `main.rs`.

Add focused tests for contract drift, parsing, field polarity, normalization,
discovery payloads, retained flags, topic expiry, reconnect replay, LWT behavior,
and tombstones. Follow descriptive test names such as `rejects_short_payloads`
and `discovery_omits_ai_by_default`.

## Commits and Releases

Use short imperative commits and keep release-version commits separate from
implementation changes. Update `CHANGELOG.md` for operational or user-visible
changes. Home Assistant update detection depends on the version in
`config.yaml`; use the release script so Cargo metadata, changelog, commit, and
tag stay synchronized. Images are published only from stable `vX.Y.Z` tags.

Do not deploy or restart the live App merely because tests pass. App management
and live verification go through Home Assistant MCP and any required approval.
